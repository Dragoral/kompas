## B. Обязательные условия

| Условие | Реализация | Статус | Осталось |
|---|---|---|---|
| Роли «Врач» и «Пациент» с раздельными правами | Роли patient / doctor (+ дежурный, admin); проверка доступа к каждому объекту — `auth.patient_for` | 🟢 | API-роутеры |
| Связь врач–пациент без третьих лиц | `Patient.doctor_id`; данные пациента сразу в его карточке, уведомление врачу в реальном времени | 🟢 | — |
| Нет самостоятельных клинических действий | Система только создаёт `ClinicalAction(status=proposed)`; назначение, отмена и направление — эндпоинт решения врача | 🟢 | UI «Подтвердить / Отклонить» |
| Сценарии с Авиандром (профиль, лечение, маршрутизация) | 5 сценариев спланированы | ⬜ | Сид-данные + автотест на каждый сценарий |
| Алертинг: признаки, экстренное оповещение, действия | 11 правил (`rules/alerts.yaml`): суицидальный риск (PHQ-9 п.9, C-SSRS, текст), тяжёлая депрессия, резкое ухудшение, серьёзная НЯ, приверженность, пропажа связи, нет ответа к 4-й неделе. Действия: мгновенно врачу, кризисный экран пациенту, эскалация дежурному, внеплановая шкала, предложение визита / паузы терапии, извещение о НР | 🟢 | Фоновая эскалация, UI алертов, замер латентности |
| Визуальное выделение направлений и предупреждений; различимы «обязательно» и «желательно» | Данные размечены уровнями | ⬜ | Дизайн (по указаниям команды) |
| Только препараты РФ в рамках инструкции; вне инструкции — решение врача | Номер РУ, показания по МКБ, блок при противопоказании, off-label — только с обоснованием врача | 🟢 | — |
| Действующие КР МЗ РФ, ИМП из ГРЛС, валидированные шкалы с лицензией | КР ID 457 и ID 301; ИМП Авиандра; источник валидации и лицензия в каждой шкале | 🟢 | Сверка редакций КР на cr.minzdrav.gov.ru (врач) |
| Законодательство РФ | `docs/compliance.md` — реестр норм со ссылками; 193н (телемедицина) заложен в логику | 🟡 | Экран согласия, раздел «О сервисе», маркировка «не медизделие» |
| Конфиденциальность | AES-256-GCM с ключом на пациента, слепой индекс, крипто-шреддинг, Argon2id, отзываемые сессии, журнал с хэш-цепочкой, push без содержания | 🟢 | Проверка тестами, заголовки безопасности |

## C. Критерии оценки

| Критерий | Чем закрываем | Статус |
|---|---|---|
| Научная обоснованность (источники указаны) | Источник у каждого правила / противопоказания / шкалы; кнопка «почему?» в UI | 🟢 / ⬜ UI |

| Удобство UI | — | ⬜ |

## D. Технические метрики

| Метрика | Как измеряем / обеспечиваем | Статус |
|---|---|---|
| Быстродействие (отклик, рекомендации, доставка алерта) | Тайминги в алерте: получено → создано → отправлено → доставлено → подтверждено; `elapsed_ms` рекомендаций; страница «Метрики» | 🟡 (поля есть) |
| Извлечение данных из историй разных шаблонов | Детерминированный экстрактор + (опц.) локальная LLM; эталонный набор от врача; precision/recall по полям | ⬜ |
| Надёжность, устойчивость к неполным/некорректным данным | Pydantic-валидация, JSON-logic не срабатывает на пропусках (а не падает); тесты на «грязные» входы | 🟡 |
| Эргономика (время/действия) | Замер в апробации | ⬜ |
| Обоснованность выводов | Источники в каждом выводе | 🟢 |
| Нагрузка | Locust: N пользователей → p50/p95 | ⬜ |
| Отказоустойчивость, бэкап, RPO/RTO, критичные данные при сбое | SQLite WAL / PostgreSQL; офлайн-очередь + идемпотентность (данные не теряются); шифрованный бэкап + замер восстановления | 🟡 |
| Кроссплатформенность | PWA + адаптивный веб врача | ⬜ |
| Масштабируемость | Stateless API, PostgreSQL, шина → Redis Pub/Sub | 🟡 |
| Гибкость архитектуры (шкалы/препараты/правила без ядра) | Всё в справочниках (YAML → БД), валидация, версии; админ-API | 🟢 / ⬜ API |
| Гибкость работы с данными | Нормализованные таблицы + JSON, индексы, фильтры в API | 🟡 |
| Полнота данных | 15 сущностей: пациент, профиль, диагнозы, терапия, назначения, приёмы, шкалы, дневник, НЯ, сообщения, алерты, клинические действия, документы, справочники, аудит | 🟢 |
| Защищённость | См. B «Конфиденциальность» + `docs/compliance.md` разд. 7 | 🟢 |
