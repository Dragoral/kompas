# Внесённые исправления — 19.10.2026

## Безопасность и доступ

- Неуспешный TOTP теперь учитывается в счётчике входа и аудите; повторно использованный шаг TOTP отклоняется. Добавлена совместимая миграция для `totp_last_step`.
- Для подключения MFA требуется повторный ввод текущего пароля; добавлен ограниченный поток первичной настройки MFA.
- Введён `must_change_password`: временные пароли новых пользователей и сбросов требуют смены перед работой; интерфейс направляет пользователя в настройки аккаунта.
- Администратор не может напрямую менять данные или сбрасывать пароль пациентской учётной записи. Смена лечащего врача оформляется запросом и должна быть подтверждена другим администратором.
- Исправлено кратковременное отображение данных предыдущего пациента при смене страницы/пути в `useApi`.
- API не публикует порт 8000 напрямую через Compose. Добавлены `.env.example`, инструкции по запуску и CLI создания первого администратора без `seed --reset`.

## Клиническая логика и устойчивость

- Приверженность считается на хронологически отсортированных дозах только активного назначения; ранний алерт ограничен минимумом наблюдаемых доз.
- В контексте добавлены отметки времени для доказательств алертов; закрытые алерты не должны повторно появляться на тех же исходных данных.
- Добавлена фиксация врачебного разбора нежелательного явления и сделана привязка проекта сообщения о НЯ к конкретному событию.
- Диагнозы валидируются на границе API (код МКБ-10, типы полей, максимум 30 записей, не более одного основного); аналитика и FHIR-экспорт устойчивы к некорректным старым JSON-записям.
- Перед назначением проверяются выбранное показание, применимость к данным пациента и ограничения дозирования из справочника; внеинструкционное назначение требует явного режима приёма и письменного обоснования врача. При возобновлении назначения повторно проверяются противопоказания и показание.
- Неизвестные или отсутствующие пределы дозирования не заменяются придуманным значением: при недостатке данных API отклоняет назначение с объяснением.
- Ошибка в шаблоне SMS приводит к записи проблемы и резервному сообщению вместо падения всего потока обработки данных.
- SSE-диспетчер использует перекрывающееся окно и дедупликацию для снижения риска пропуска событий с поздним commit. Врач получает живые алерты на всех страницах и отправляется квитанция доставки; пациентский интерфейс получает кризисные и терапевтические статусы.
- Нормализуются timezone-aware клиентские временные отметки, а синхронная работа с ticket/БД вынесена из асинхронного SSE-цикла.
- Добавлена реализация зашифрованного backup/restore drill для PostgreSQL и расписание запуска с задержкой, но live-проверку на PostgreSQL нужно проводить на целевом стенде.

## Интерфейс и документация

- Врач видит этапы клинических рекомендаций, источники, причины/срочность маршрутизации и поля дозы/частоты в форме назначения.
- Добавлена панель смены лечащего врача с двухсторонним подтверждением.
- Создан `README.md`, обновлён `docs/requirements_matrix.md`, добавлены безопасные параметры по умолчанию и примеры конфигурации.
- Непроверенные шкалы и рекомендации получают заметное предупреждение; препарат с `verified != true` нельзя назначить через API. В `APP_ENV=production` запуск останавливается при обнаружении непроверенных клинических справочников. Для локальной демонстрации используется `APP_ENV=development` и только синтетические данные.

## Проверки

- Backend: **64 теста прошли** (`64 passed in 6.62s`) в полном успешном прогоне с временным RFC 6238-совместимым `pyotp` shim только в `/tmp`. Без shim штатный запуск блокируется отсутствующим пакетом `pyotp`; перед релизом повторить прогон с установленной официальной зависимостью.
- Python `compileall`: успешно (`app`, `tests`, `tools`).
- YAML: 21 YAML-файл прошёл разбор.
- TypeScript/TSX: 72 файла прошли синтаксический разбор через TypeScript `transpileModule` без diagnostics. Полноценные `tsc`, lint, Vitest и frontend build не подтверждены: отсутствуют npm-зависимости и локальный кэш не содержит всех требуемых пакетов (`npm ci --offline` → `ENOTCACHED`).
- PostgreSQL, настоящий провайдер SMS, миграция существующей БД, HTTPS и эксплуатационная устойчивость не тестировались на целевой инфраструктуре.

## Что намеренно не отмечено как выполненное

- Клинические флаги `verified` не переключались автоматически. Тексты валидированных русскоязычных шкал, дозировки, показания, противопоказания, правила маршрутизации и КР должен проверить специалист по актуальным официальным источникам.
- Реальный экстренный канал SMS/звонка необходимо настроить и протестировать; в режиме `NOTIFY_PROVIDER=log` сообщения только журналируются.
- Базовые PWA manifest/service worker и зашифрованная очередь ограниченных пациентских POST-записей добавлены, но проверка установки PWA, реального offline/online восстановления и восстановления после закрытия браузера не выполнена.
- Не проводились юридическая оценка, испытания с реальными пациентами, SUS/UX-апробация и формальные нагрузочные замеры.
